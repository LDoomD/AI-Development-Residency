## How to read this log

- State: observed (I saw it in a file or commit), documented (a saved report says so), inferred (my reading), reported (someone told someone, e.g. a memory note), not-assessed.
- Cause categories (exact names): (1) stale or partial source, (2) claimed more than the evidence showed, (3) assumption about the user or audience, (4) missing or changed definition, (5) upstream deliverable changed after downstream work began, (6) data or tool limit, (7) acted without the owner asking, (8) communication or jargon, (9) project or scope pivot.
- Detector: owner / Claude / audit / script.
- Added category (10) copying or counting slip: used only where no listed category fits (a wrong number, a swapped count, a wrong match key).
- Added category (11) existing rule not followed: used only where the error was a rule already written down that was simply missed, and no content category fits.
- Evidence tokens: `git:<hash>` = commit; `mem:<file>` = owner memory note; `dog:<file>` = Dog Feeding Docs report; other paths are repo files. Text in << >> is an exact quote (at most 20 words), machine-checked by `scripts/check_log.py`.
- Memory-note dates: the note text gives the date of the incident; the file `modified:` stamps are UTC.
- A row's "state" in the last column: obs = observed in a file or commit; doc = documented in a saved report; inf = my inference; rep = reported (a note says so, not re-checkable).
