# Week 5 Coding Challenge — PenTest a Code Base

## How to Submit

Email your teacher the link to your Github repository: mdenner@techfleet.org

## Summary

It's not enough to code the app; you must secure it too! This subject matter called "Secure Coding Principles", and the subject called "Network Security" are two crucial components of enterprise-ready applications. You are going to live as a White Hat Hacker this week: trying to hack your own code base to identify the fixes that you need to make on Claude Code.

## Standard Residency Objective

Take either your Week 3 application or your Week 5 application and perform a full Penetration Test (AKA a PenTest) with Claude Code. Utilize Claude agents during the PenTest. Generate a full report from the PenTest.

## Premium Residency Objective

**You are doing the same thing as the standard residency students.**

## Tools

Notion, Claude Code, OWASP Cheat Sheet Series, WireShark MCP, Cloudflare, Aikido

## Deliverables

Penetration Test Summary

## Requirements

1. PenTests and non-feature work also needs written requirements! Make new product requirements (only vision and scope and technical requirements) for this work. Use the Week 2 templates for guidance on what to write. Put it in a Notion document.
2. Add the specifications to your kanban board and put the ticket into the proper status.
3. Take your Github repo from Week 3 or Week 5 and hack it using the PenTest procedures.
4. Research what makes a good PenTest and ensure you cover all areas of the PenTest.
5. Integrate your code base with Aikido and analyze the code base, fix all of the findings.
6. Take the OWASP cheat sheet series and create a series of ways that you can test for every single cheat sheet item (there are over 100 ways to get hacked! Test them all!)
7. Write a one page summary (NOT USING AI) of what you did and what you learned when you submit the work to me.

## To Submit

USE THE PREVIOUS GITHUB REPOSITORY FROM WEEK 3: "AI DEVELOPMENT RESIDENCY - WEEK 3 - APP"

Use the submission template.

Produce a "Security Testing Report" with all of the findings, fixes, and decisions that were made. Push all of the NEW code, security report doc, and the submission template files you produce into the repository through a merge.
